mongo集群搭建与异常恢复

1. 架构选型与推荐拓扑

1.1 副本集（Replica Set）

  • 最小生产推荐：3 个数据节点（1 Primary + 2 Secondary），奇数投票。

  • 可选：

    • Hidden 隐藏节点（只备份/报表）
    • Delayed 延迟节点（用于回滚防护，如延迟 1–24h）
    • 不再推荐仲裁节点（Arbiter）——除非存储资源极端受限。

示意

1.2 分片集群（Sharded Cluster）

  • 组件：mongos 路由 + Config Server Replica Set (CSRS) 3 节点 + 多个分片（每个分片是一个副本集）。
  • 适用：数据量/并发量较大，需要水平扩展或不同数据域拆分。

示意

2. 环境准备

  • OS：x86_64 Linux（CentOS / RHEL / Ubuntu 等）
  • 目录：/data/mongo/{rsX}/db, /data/mongo/{rsX}/log
  • 时钟同步：chrony / ntp
  • 句柄与进程数：/etc/security/limits.conf
  • 关闭透明大页（THP）、保持 numactl 合理策略
  • 打开 TCP：27017（mongod）、27018（config）、27019（mongos，任选），并限制安全组
  • 持久化：ext4/xfs，关掉磁盘写缓存欺骗，RAID 带缓存需电池保护
  • 内存与缓存：WiredTiger 缓存默认约为内存的 50%；可用 storage.wiredTiger.engineConfig.cacheSizeGB 调整

7. 异常恢复场景与处理手册

7.1 主节点故障（Primary Down）

现象：写入失败、选举中、延迟升高
处理：

  1. 等待自动选举（通常 < 10s）。

  2. 如需手动转移主：在当前 Primary 执行

  3. 恢复原主机：检查磁盘/网络/日志，修复后作为 Secondary 加回。

7.2 节点数据损坏/落后太多

现象：节点无法启动、或 RECOVERING 长时间无法追上
处理：强制重新初始同步（重新拉全量）

若所有 Secondary 都落后且 oplog 不足以追上：从最近一次全量+增量恢复。

7.3 发生回滚（Rollback）

触发：网络分区导致双写，旧主恢复后发现与新主数据分歧
处理：

  • 短期：MongoDB 会将回滚的文档写入 rollback 目录（WiredTiger 日志）。

  • 中期：从业务侧确认差异数据，以新主为准合并必要数据。

  • 预防：

    • 使用延迟节点（Delayed Secondary，如延迟 1–24h）便于人工恢复错误写入；
    • 业务端启用幂等写与重试写（writeConcern: “majority”）。

7.4 磁盘写满

现象：WriteConcernFailed、No space left on device
处理：

  1. 立即扩容/清理：压缩日志、清理历史备份、扩展卷。
  2. wiredTigerEngineRuntimeConfig 不建议随意改。
  3. 恢复后检查：db.serverStatus().wt.cache、df -h、iostat。

7.5 网络分区/延迟大

  • 检查：rs.status() 中 pingMs、系统 ping / mtr。
  • 保证副本集多数节点在同一可用区，避免脑裂。
  • 必要时下调受影响节点 priority: 0 或 votes: 0，以免选为主。

7.6 配置误改/副本集重配

变更期间避免在高峰时段操作。

7.7 分片集群异常

Balancer 失衡

Chunk 卡住迁移

某分片不可达

  • 暂停写入或将路由权重转移，紧急情况下可对热点集合进行 moveChunk 到健康分片。

8. 性能与参数要点

  • writeConcern: { w: "majority", j: true }：保证已提交到多数节点且落盘
  • 适当的索引（前缀/复合/稀疏/TTL）；避免“全表扫描 + 大返回集”
  • 连接池：驱动层配置 maxPoolSize、waitQueueTimeoutMS
  • 慢查询日志：profile 或 systemLog.component.accessControl.verbosity
  • 大集合分片前评估分片键基数与热度（避免单分片热点）

9. 安全与合规

  • 仅对内网开放端口；必要时启用 TLS（x.509）
  • 角色最小化授权：readWrite、clusterMonitor、backup 等
  • 审计：auditLog.destination: file（企业版/社区替代方案）
  • 定期轮换 keyFile（需滚动重启）

10. 日常巡检清单（可作定时任务）

  • 副本集与分片健康：rs.status()、sh.status() 无 RECOVERING/ROLLBACK
  • Oplog 覆盖窗口 ≥ 24–72h（rs.printReplicationInfo()）
  • 磁盘使用率 < 70%，iowait 正常
  • 慢查询数量与 P95/P99 延迟
  • 备份成功率 100%，每月恢复演练一次
