一个简易直播软件的开发

用 Go 实现的简易直播（WebRTC）——完整方案与代码

下面给出一个能跑通的最小可行直播系统（MVP）：

  • 主播端：浏览器采集音视频（getUserMedia），通过 WebRTC 推流
  • 观众端：浏览器通过 WebRTC 拉流
  • 后端（Go）：用 pion/webrtc 做“轻量 SFU”，用 WebSocket 做信令
  • 特点：跨平台、零插件、延迟低（~亚秒级），代码量小，便于二次开发

说明：此方案为教学/原型用途，未接入 TURN，NAT 复杂环境可能需要自行配置 TURN 服务器；生产可扩展为多房间、鉴权、录制、转 HLS 等。

二、运行步骤

启动后打开浏览器访问：

  • 主播端：http://localhost:8080/publisher.html
  • 观众端：http://localhost:8080/viewer.html

如果需要公网访问，请将服务部署到有公网 IP 的服务器，并确保 8080 端口可达；若观众与主播在不同 NAT 背后，建议配置 TURN。

三、核心思路（简述）

  • 主播连上来后，服务端创建一个 PeerConnection，拿到上行 Track（音/视频）。
  • 服务端为每个媒体类型各创建一个 TrackLocal（可复用），把主播上行的 RTP 包**转发（复制）**到这个本地 Track。
  • 每个观众连上来都会新建自己的 PeerConnection，把上述本地 Track 添加到观众的 PC，从而实现一推多拉的简易 SFU。

六、常见问题与优化建议

  • 没有画面/声音

    1. 先确保主播端已“开始直播”；
    2. 浏览器是否允许麦克风/摄像头权限；
    3. 不同网络/NAT 复杂：考虑部署 TURN（如 coturn），并在后端/前端 iceServers 中加入 TURN。

  • 多个主播/多房间

    • 使用 roomID 维度管理：map[roomID]*Room，每个房间维护自己的 publisherPC、globalVideo/globalAudio、viewers 集合。
    • 信令消息中加入 roomID 字段，并在前端传入。

  • 录制 / 回放 / 转 HLS

    • 服务端在收到 TrackRemote 时，写入文件（WebM/OGG）或送到 gstreamer/ffmpeg；
    • 也可转推到 RTMP（推到 Nginx-RTMP/媒体服务器）再切 HLS 以适配纯 HTTP 播放。

  • 鉴权/限速/监控

    • 在 /ws 处做 Token 校验；
    • 接入 Prometheus/Grafana 观察连接数、比特率；
    • 观众上限控制与 QoS（如按房间限流）。

  • 更稳重协商

    • 代码里对“热插拔 Track”采取了“弱重协商”策略，简单场景可用；若遇到兼容问题，请实现完整的 Offer/Answer 轮转并在前端处理 negotiationneeded。
